## 2. Objetivo da alteração

* resumo (4-6 linhas):
  Substituir o backlog vazio por tarefas anatômicas derivadas diretamente do project-guide, garantindo alinhamento ao MVP-1. Cada tarefa precisava seguir o template oficial (IDs, critérios, testes, rollback) e respeitar o pipeline INSIGHT→USE-CASE→TO-DO. A meta incluía apontar dependências, prioridades e referências a use cases coerentes com os componentes descritos no guia.
* escopo (inclui/exclui):
  - Inclui: atualização completa de `code-brain/to-do/tasks.yaml`, validação YAML, documentação desta mudança.
  - Exclui: criação de novos arquivos de use-case, alterações em context.yaml ou automações adicionais.

## 3. Decisões e justificativas

* alternativas:
  1. Reaproveitar apenas as tasks antigas (inconsistentes) – rejeitado.
  2. Criar backlog minimalista sem critérios/testes – rejeitado por violar template.
  3. Redigir tasks anatômicas cobrindo cada feature do MVP-1 com critérios e planos de teste – aprovado.
* decisão:
  - Criar cinco tarefas estruturais (context manager, pipeline cognitivo, templates, integração Git e validação) com dependências explícitas e prioridades P0/P1.
* riscos/limitações (com mitigação):
  - Falta de use cases formalizados: use of IDs UC-0001..UC-0004 alinhados às seções do project-guide e documentados no backlog para futura materialização.
  - Necessidade de lint obrigatório: mitigado rodando `yamllint` após ajustar largura de linhas.
