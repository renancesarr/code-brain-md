## 2. Objetivo da alteração

* resumo (4-6 linhas):
  Atender às T-0003/T-0005 consolidando templates essenciais e estabelecendo validação básica de documentação. Era necessário atualizar os templates (developer-notes e project-guide) para refletir o pipeline atual, criar uma guideline operacional para validações e garantir que o estágio TEST use um script padrão. O contexto e o backlog precisavam reconhecer a conclusão das tarefas.
* escopo (inclui/exclui):
  - Inclui: atualização de templates Markdown, ajustes no prompt/context/backlog, evolução do script `validate-docs`, execução do script e registro em log.
  - Exclui: evolução do workflow Git (T-0004), criação do repositório físico para `IN/UC`, mudanças no project-guide final.

## 3. Decisões e justificativas

* alternativas:
  1. Manter os templates como estavam e apenas documentar o processo – rejeitado por não atender aos critérios de clareza e instruções explícitas.
  2. Depender de ferramentas externas (markdownlint via npm) para validação – rejeitado para evitar dependências fora do ecossistema atual.
  3. Atualizar os templates e criar um script de validação sem dependências extras, integrando-o ao prompt/context – adotado.
* decisão:
  - Reescrever `developer-notes.template.md` e `project-guide.template.md` com instruções alinhadas ao AGENTS e ao pipeline cognitivo, além de introduzir o script `validate-docs.sh` (com verificação YAML via `yamllint` e lint básico de Markdown em `validate-docs.py`).
* riscos/limitações (com mitigação):
  - Script ainda não integra CI: mitigado registrando ação futura (pendente na seção de próximas ações do backlog e no contexto).
  - Necessidade futura de repositório dedicado para `IN/UC`: anotado em `context.yaml::pending_validations`.
