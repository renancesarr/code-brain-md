## 2. Objetivo da alteração

* resumo (4-6 linhas):
  Entregar a T-0004 padronizando o fluxo Git: branch `feature/UC-XXX/TXXX`, commits `type(scope): msg`, PRs com checklist e preflight obrigatório. Era necessário atualizar o workflow template oficial, alinhar as guidelines, registrar o script de validação/preflight no contexto e encerrar a pendência no backlog/tasks. O resultado deve permitir que qualquer agente siga um roteiro único para branches, PRs e validações.
* escopo (inclui/exclui):
  - Inclui: reescrita de `code-brain/git/workflow-template.md`, ajustes nas guidelines Git, atualização de `context.yaml`, `tasks.yaml`, `backlog`, validação do repositório e log IA.
  - Exclui: automação de CI/preflight, alterações no preflight.sh em si.

## 3. Decisões e justificativas

* alternativas:
  1. Manter o template minimalista e apenas referenciar documentos existentes – rejeitado porque não atendia aos critérios de aceitação da T-0004.
  2. Criar um novo documento separado do workflow – rejeitado para evitar múltiplas fontes de verdade.
  3. Centralizar todo o fluxo no workflow template e reforçar as regras nas guidelines Git – adotado.
* decisão:
  - Documentar o ciclo completo (branch → desenvolvimento → preflight → PR → pós-merge) e atualizar `guidelines.md` para exigir `preflight.sh` + `validate-docs.sh` com registros em log.
* riscos/limitações (com mitigação):
  - Script preflight ainda depende de npm/testes não configurados: documentado como pré-requisito; integrar ao CI está listado nos próximos passos.
  - Possível drift entre workflow e guidelines: anotado na seção de recursos e no backlog para acompanhamento.
